# Keyshotvv 专题归档规则

- 与48K纯白、Trade C同级。原始范围为北京时间2023-11-06起至首次实际检查，之后每日增量；按月记录检索覆盖，不将无结果等同于作者未发帖。
- 收录全部交易相关经验、教学、视频、盘前分析、交易记录、复盘及实质作者回复；排除闲聊、广告、无附加观点的转发。引用别人内容明确归属。
- 单篇使用“YYYYMMDD-清晰标题/同名Markdown/专属imgs、videos、subtitles”，同名时加来源ID。只保留title、source、date三个属性；内部链接用wikilink。
- 来源原文、作者补充、编辑解释分区。长文不得用搜索摘要代替。图表逐张核验，不保存独立头像。收益、胜率、成交均保留为作者自述；不拼接不同阶段规则，不补造入场、止损、仓位或胜率。
- 视频保存原视频、带时间戳字幕、详细分段中文笔记及必要关键画面。优先原字幕，否则项目隔离环境本地转写。不得上传第三方转写。机器字幕须标记，听不清处明确标注，未校对不算完成。
- 核验与断点见docs/runbooks/keyshotvv-archive/state.json。历史月份与每日成功边界独立；按主帖和回复ID去重，重叠回查至少一天。失败不推进成功边界，下载成功不等于整理完成。
- 每日沿用automation-2的北京时间17:30任务。配置已保存与自然运行已验收分开记录。已有来源先补媒体/字幕/回复，不创建重复笔记。
- 不删除、覆盖其他专题或重编电子书。无源内容不可伪造；失败保留原因及补查入口。

- 视频查漏必须扫描所有来源的媒体字段、外链与频道，不只看内容分类；同课跨平台去重，统一完成清单为video-work-report.json。
- 图片语义核验按文件哈希保存；回复归属按原始reply_to_results逐级追溯，不能凭时间接近或内容相似猜配主帖。
- 已不可得正文、引用和上级问题分别列缺口；同窗重复运行必须保留已编辑正文及独立历史/每日边界。

- 每日归档唯一生产入口为docs/runbooks/keyshotvv-archive/archive_batch.py daily --record <真实记录JSON> [--commit]；由协调器完成构建、上下文、覆盖、索引、核验后调用daily_commit.py预检及CAS提交。已核验真实记录的正式失败保存区间与pending来源ID，不推进边界；历史补档用archive_batch.py history。所有state生产读改写使用.archive-state.lock及原子替换，详见每日提交说明；不手改daily.last_success。
